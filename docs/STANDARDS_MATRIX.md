# Standards-oriented development mapping (not compliance claims)

| Reference | Relevant topic | Evidence in v0.5 | Gap to formal conformance |
|---|---|---|---|
| IEC 62304:2006+A1:2015 | Software life-cycle process | Versioned requirements, code tests, release checklist and model safeguard tests | No organizational QMS, lifecycle plan approval, independent reviews or complete safety classification |
| ISO 14971:2019 | Risk management | Initial research hazards and controls | No validated complete hazard identification, acceptability criteria, residual-risk evaluation or post-market cycle |
| ISO 13485:2016 | Quality management | Structured documents and local release/record history (not a QMS) | No certified QMS, document approvals, training, CAPA, supplier processes, audits |
| IEC 62366-1 | Usability engineering | Safety banner, explicit absence of alarm result | No formal use specification, summative usability validation or use-related risk file |
| IEC 81001-5-1:2021 | Secure software lifecycle | Threat model, local-host/origin guards, input validation and regression tests | No secure-development organizational framework or penetration test |
| IEC 60601-1-8 | Medical electrical equipment alarm systems | Reference only: system never connects to an actual alarm system | No physical medical electrical equipment and NO claims of alarm compliance |
| FDA QMSR (effective Feb 2 2026) | US regulated manufacturing QMS | Useful background to professional development | Prototype not a finished medical device manufacturer; no QMS implementation |
| IMDRF/GMLP AI principles | AI model evidence | Segregated retrospective pipeline, held-out patient groups and warnings | No clinical external performance evidence, bias studies or deployment monitoring |

Standards have licensing and jurisdictional requirements. This project does **not** reproduce paid standard text. Review authorized official documents with regulatory professionals before claims of conformance.
