# WaveAssure v0.13 — Historical waveform replay and custom research data

**Research / education only. Not live monitoring, a clinical alarm, alarm suppression, diagnosis, or validated arrhythmia detection.**

## Replay

1. Load a synthetic waveform, a previously stored record, a local WFDB record, or an imported custom file.
2. Use **Play recording / Pause recording**, the speed selector (0.5×, 1×, 2×, 4×), the window start slider, and the window length selector. This is **retrospective playback**, not a live ECG feed.
3. The timestamp shown is seconds elapsed from the **start of this recording**. No absolute date/time or original buzzer audio is supplied by standard waveform recordings.
4. **Jump to alarm** is enabled only when the record has a documented event annotation or a timestamp the user entered.
5. The optional brief preview tone is **generated by the browser**, off by default, and is *not* a recording of the original patient monitor. It makes no medical alarm claim.
6. Playback is paused when navigating to another section or hiding the browser tab. Refresh speed depends on the size of the recording and the computer.

### Alarm sources

- Labelled VTaC records: local `event_labels.csv` matching the exact record can establish the **dataset's documented alarm onset at 300 s** for full-length recordings. The label and event-time metadata are external annotations, **not a WaveAssure prediction**, and the CSV itself is not authenticated against the official PhysioNet release by import alone.
- Custom CSV and manually uploaded WFDB: you may supply an alarm timestamp in **seconds from the first sample**. It is clearly marked as **user-entered / unverified** and no True/False VT reference label is assigned.
- Unlabelled recordings: **no marker**, no buzz time inferred, no claim that an alarm occurred.
- Fault-injected derived records: **original annotation intentionally does not transfer**.

## Import custom CSV

1. Select a **de-identified** `.csv` file up to **8 MB**.
2. Choose the time column and whether its values represent seconds or milliseconds. The time axis must start near zero and be approximately evenly sampled (within 2%).
3. Select between **1 and 8 signal columns**, then choose the correct signal type/units for each: ECG (mV), PPG (a.u. or NU), or arterial pressure (mmHg). The software does **not** convert arbitrary or unknown units; if you cannot verify units, do not import as a calibrated signal.
4. Optionally enter a research alarm timestamp. Click **Import mapped CSV**.

The importer requires at least 100 points and no more than 100,000 samples per channel, sample rate 50–1000 Hz, maximum recording duration 600 seconds. Identifying column headers are rejected, but **this is not a de-identification validator**: remove names, IDs, dates, location details, or other personal information before importing. If the CSV has nonuniform timestamps, preprocess it offline rather than inventing a new sampling rate.

Original legacy columns (`time_s`, `ECG_mV`, `PPG_au`, `ABP_mmHg`) remain supported.

## Import custom WFDB

In **Data source**, select a matched header (`.hea`) and waveform (`.dat`) pair and click **Import selected WFDB pair**. Supported only: **single shared-file, little-endian WFDB format 16**, 1–8 bounded ECG/PPG/ABP channels, same basename, valid ADC gain/baseline and checksums. This is **not** a universal WFDB/DICOM/EDF importer. Header limit 8 KiB, interleaved signal data limit 1.6 MB. File parsing occurs locally; the file contents are sent only to the loopback application. User-uploaded WFDB files remain **Unlabeled** regardless of any original event list.

For official VTaC files already stored in `D:\WaveAssure-Datasets`, the original relative-path import remains supported and can match `event_labels.csv`; the browser file picker cannot grant verified dataset provenance.

### Troubleshooting

- **No signal channels selected:** select the desired CSV waveform columns and their correct kind/units.
- **CSV time error:** choose the correct time column and milliseconds/seconds setting, or trim/rebase your file to start at 0 with uniform sample intervals.
- **WFDB mismatch:** check basename, compatible format, layout, physical units, file length and checksums. Multi-segment, compressed and other WFDB formats remain unsupported.
- **No alarm marker:** the recording has no documented alarm timestamp. Entering a timestamp does **not** establish that a real alarm occurred.
- **Replay appears slow:** large recordings are read and decimated by the local server. Pause, choose a shorter window, or reduce playback speed. No claims about real-time throughput are made.

### Verification scope

Unit tests check exact sample timing, format-16 integrity, rejection of corrupted/misaligned files, optional alarm provenance and text labels. A separate simulated browser/real API bridge covered playback, CSV mapping, two-file WFDB upload, the alarm marker, light mode and a 390 px viewport. **A physical Windows browser/network acceptance test and performance benchmark are still outstanding.** No patient-data classifier training, clinical performance evaluation, ethics approval or regulatory authorization was performed.
